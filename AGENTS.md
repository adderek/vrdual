# AGENTS.md — vrdual handoff for AI agents

Read order: this file → [TODO.md](TODO.md) → the task file you pick →
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (how it works, config reference) →
[docs/PLAN.md](docs/PLAN.md) (option space, decisions, why).

## What this is

App-unaware stereo VR on two GPUs. One process per eye: a Vulkan layer hides
all but one GPU, patches every vertex shader to shift clip-space X by the eye
offset, and exports presented frames to `/dev/shm`. A compositor pairs L[F] and
R[F] side by side. IPD/anchor/HFOV change live through a shared control block.
Status: M0 (PoC) + M0.1 (config, live IPD, calibration) done 2026-10-09.
2026-10-18: mirror mode (one process, `VRDUAL_EYE=both`, hidden 2nd GPU), Steam
(Flatpak) + 32-bit + OpenGL via Zink (Zen Bound 2 runs), OpenXR output
(`vrdual-xr`, tested on Monado simulated HMD and in the Quest 3S via WiVRn:
Zen Bound 2, per-eye parallax confirmed by the user).

## Golden rule

`./vrdual selftest` must pass before you start and after every change (exit
0). It takes ~1 min and opens a few small windows (needs `make lib32` deps and,
for the OpenXR check, a Monado build in `build/monado/`, else SKIP). When you add behaviour, add a
check to `vrdual_selftest` in `_`. "Done" means selftest passes plus a new
check for the new behaviour, or a stated reason why it cannot be checked
automatically.

## Commands

```bash
./vrdual build                # make; outputs in build/
./vrdual selftest             # THE check
./vrdual ci                   # its GPU-free part (seconds, no windows); GitHub CI runs it
./vrdual run --session S -- APP ARGS   # any Vulkan app, one copy per eye
./vrdual-ctl / ./vrdual live|set|save  # live control of session S (VRDUAL_SESSION or --session)
./vrdual clean                # stale /dev/shm/vrdual-* from manual runs
./vrdual version              # build identity of tools, layers and the Steam copies
```

Manual layer use: `VK_ADD_LAYER_PATH=$PWD/build VK_INSTANCE_LAYERS=VK_LAYER_VRDUAL_stereo VRDUAL_EYE=left VRDUAL_SESSION=x APP`.

## Dependencies

Build: `g++` (with 32-bit multilib for `make lib32`), `glslc` (shaderc), SDL3,
the Vulkan loader, X11/xcb/GL headers. `selftest` also needs `spirv-val`,
`magick` (ImageMagick), `python3` and Pillow (`tools/wiggle.py`, the only
non-stdlib Python dependency); `--record` needs `ffmpeg`. Vulkan headers are a
submodule, OpenXR headers are vendored (both in `third_party/`), no system
package. Packages per distro: [INSTALL.md](INSTALL.md); details: ARCHITECTURE
"Commands".

## Reference test machine (host "fractal")

Results in `docs/GAMES.md`, `site/games.json` and the docs come from this
machine unless a row says otherwise. Read them with its topology in mind:

- Two RX 7900 XTX (RADV, Mesa 26), Arch Linux, GNOME on Wayland.
  - **display GPU**: drives the monitor and the desktop; the app's GPU under
    `auto` (left eye, mirror device A). Here behind the B550 chipset,
    **PCIe Gen3 x4**, no PCIe atomics.
  - **headless GPU**: no monitor; right eye, mirror twin, WiVRn server. Here
    CPU-direct **Gen4 x16**.
  - Role follows the monitor cable, link speed follows the slot; the pairing
    above is today's wiring, not a rule. Docs name GPUs by role (or by slot
    when bandwidth matters), never by PCI address; selftest detects both from
    sysfs. Current addresses: `./vrdual gpus` (local notes: AGENTS.local.md).
  - DRM cardN and ROCm indices are swapped relative to each other here (hence
    the PCI-address rule below).
- Portrait desktop monitor (X reports `DP-2 2880x5120`): fullscreen games pick
  2880x5120 (see Conventions).
- Steam is the Flatpak; headset Quest 3S via WiVRn.

## Invariants / decisions (don't relitigate without new evidence)

- The layer stays **passive**: no UI, network, threads or prompts inside the
  app process. UIs edit the control block; layers only read it. See PLAN §H.
- App-unaware is the point. No changes to apps or engines.
- Config precedence: defaults < `[global]` < `[app:NAME]` < `VRDUAL_<KEY>` env.
  `VRDUAL_EYE`, `VRDUAL_GPU` and `VRDUAL_SESSION` are per process only.
- Changing a struct in `vrdual_shm.h` → bump `VRDUAL_VERSION` or the ctl `version`.
- HMD path = OpenXR app with WiVRn as the runtime (Quest 3S). Quest Link and
  Virtual Desktop are Windows-only; ALVR needs SteamVR. See PLAN §F.
- One fixed (far) IPD is geometrically correct without eye tracking; `ipd_near`
  is an opt-in perceptual tweak (ARCHITECTURE "Near/far IPD").

## Gotchas already paid for

- Zink (Mesa 26) refuses a Vulkan 1.4 driver whose reported apiVersion is
  clamped to 1.3 ("failed to load driver: zink") — hide features, not versions.
- GPL link pipelines come with `FAIL_ON_PIPELINE_COMPILE_REQUIRED`: A hits its
  cache, B returns `VK_PIPELINE_COMPILE_REQUIRED` + null → strip the flag for B.
- Layer globals must never be destroyed: driver threads call in during exit.
- DXVK 3 (Proton) refuses a device without `bufferDeviceAddress`,
  `maintenance5`, `maintenance6` ("No adapters found" in the Proton log). The
  mirror replays device addresses (capture/replay) instead of hiding them.
- A mirror stop must leave the app intact: shadow mappings keep being copied
  to A afterwards (otherwise the game renders stale data and crashes).
  32-bit games: address space, see "Host memory" in ARCHITECTURE.
- Test windows hidden behind others get ~1 frame/s from XWayland/Mutter: wait
  for frame indices in checks, never for a fixed time.
- One process can have several live swapchains (wined3d). Never size the frame
  file from one swapchain and publish from another (`shm_claim`).
- `/dev/uinput` fails with ENODEV after a kernel package update until reboot
  (the running kernel's modules are gone). The input test then skips.
- WiVRn listens on a dual-stack IPv6 socket: with `ipv6.disable=1` on the
  kernel cmdline, `wivrn-server` dies with "Address family not supported by
  protocol". Drop the boot parameter; to keep IPv6 off use the sysctl
  `net.ipv6.conf.{all,default}.disable_ipv6=1` instead.
- NVIDIA: glvnd hands GL apps NVIDIA's own GL, so `MESA_LOADER_DRIVER_OVERRIDE=zink`
  alone does nothing and the layer never sees the game. Also set
  `__GLX_VENDOR_LIBRARY_NAME=mesa` (the Steam wrapper does).
- DXVK passes vertex shaders inline (maintenance5: `VkShaderModuleCreateInfo`
  in the stage pNext, no module); the layer patches them in
  `vkCreateGraphicsPipelines`. Symptom when missed: identical eyes, no 3D.
- A second VkDevice on the same GPU cannot replay the first one's device
  addresses (NVIDIA: shared VA) — hence alternate-eye rendering for single GPU.
- Proton logs: Steam writes none by default. The installed wrapper sets
  `PROTON_LOG=1` (`vrdual install`), log lands in
  `~/.var/app/com.valvesoftware.Steam/steam-<appid>.log`. Launch with
  `flatpak run com.valvesoftware.Steam steam://rungameid/<appid>`. gdb cannot
  attach across pressure-vessel's PID namespace; bisect via the wrapper.

- Games may leave the swapchain's alpha at 0 (Call of Juarez Gunslinger;
  Hogwarts Legacy: only the GUI has alpha 1). WiVRn shows alpha 0 as black,
  so the layer exports alpha forced to 1 (selftest `--clear-alpha 0` check).
- Mirror memory sync was a full `memcmp` of all mapped memory per submit
  (26 ms over 336 MB). Shadows now use userfaultfd async write-protect +
  `PAGEMAP_SCAN`; works inside Flatpak Steam here (unprivileged, needs
  `UFFD_USER_MODE_ONLY` since `vm.unprivileged_userfaultfd = 0`). Cached
  (driver-mapped, HOST_CACHED) memory is shadowed too since 2026-10-21, with
  write-back of what A's GPU writes into host memory (recorded copy/fill
  commands, copied at the app's fence/semaphore sync). The older `cached_wp = 1`
  (mprotect on the driver's mapping) breaks kernel writes (EFAULT: Alice's
  textures flickered black); importing host pages into A fails on amdgpu
  userptr (ARCHITECTURE "Host memory").

- `glslc` segfaults on `GL_EXT_buffer_reference_uvec2` with constant operands;
  `glslangValidator -V` works.
- SPIR-V inserts must respect section order: capabilities → extensions →
  ext-inst imports → memory model → … → globals before the first `OpFunction`.
  Live mode switches the addressing model to `PhysicalStorageBuffer64`.
- Layer-allocated dispatchable objects (command buffers) need
  `pfnSetDeviceLoaderData`.
- If the app chains `VkPhysicalDeviceVulkan12Features`, adding a separate BDA
  features struct is invalid. The layer flips the app's flag and restores it.
  If the app uses `VK_EXT_buffer_device_address`, live mode is off (baked fallback).
- The swapchain gets `TRANSFER_SRC` usage added for readback. Present waits on
  the layer's semaphore, which is signalled after the copy.
- Address GPUs by PCI address, never by DRM cardN or ROCm index: the two
  orders need not agree.
- The test app picks MAILBOX so occluded windows don't stall FIFO (Wayland).
- Measuring parallax: use `--scene calib` (static, known distances). The
  rotating cubes scene is only good for eyeballing.

## Conventions

- `_` = humans (menu); `vrdual` = machines (no prompts, stdout data). New
  operations become subcommands in `_`, not new top-level scripts.
- Code comments and docs in English; match the existing terse comment style.
  Keep explanations concise and technically precise. The maintainer writes in
  Polish, is a senior engineer and prefers terse answers.
- Git repo since 2026-10-18 (`master`, remote `origin` = github.com:adderek/vrdual). Vulkan-Headers is a
  submodule (`git submodule update --init`). Releases (maintainer, all local, no
  CI): tag `v0.x.y`, push it, `tools/release.sh --publish v0.x.y` (tarball with
  the submodule, notes from CHANGELOG.md, 0.x = pre-release); `.gitattributes`
  keeps agent/task files out of archives and fills in `VERSION`. Commit only
  when the user asks.
- Flatpak Steam (`~/.var/app/com.valvesoftware.Steam`, the tested setup): its
  `/dev/shm` is private, `$HOME` inside = that dir. Test games by hand with
  `flatpak run --command=bash com.valvesoftware.Steam -c '...'` (see ARCHITECTURE
  "Steam"); never `pkill -f` a pattern that matches your own shell command.
- Fullscreen games pick the desktop's resolution: on a portrait or very large
  desktop the HMD shows a tall screen, and Portal 2 (Source) renders only part
  of it correctly. Use `-windowed -w 1920 -h 1080` or the game's resolution
  setting.
- Steam games load a copy of the layer (`vrdual install`, old name
  `steam-install`; `vrdual xr` refreshes it at every start). After a layer
  change, re-run it or restart `vrdual xr`, or the game silently runs the old
  layer. A game already running keeps the layer it loaded.
- Debug crashes inside the Flatpak: `coredumpctl dump` + gdb with a sysroot of
  symlinks to `/var/lib/flatpak/{app,runtime}/…/files`.

## Local environment

If `AGENTS.local.md` exists, read it before you start: it holds constraints
of the local workstation (other services on the GPUs, processes you must not
touch, known instabilities, permissions, installed tools). It is not tracked
by Git (`*.local.md`); Claude Code loads it through `CLAUDE.local.md`
(`@AGENTS.local.md`), other agents must open it themselves. Everything above
works without it.
